## The challenge (Track 01 — Biology)

Build **two** classifiers that read a peptide sequence (a string like
`KWKLFKKIGAVLKVL`) and output a probability:

1. **Anticancer** — probability it kills cancer cells.
2. **Hemolytic** — probability it damages healthy red blood cells.

Then cross the two into a verdict:

| Anticancer | Hemolytic | Verdict |
|---|---|---|
| 1 | 0 | `Selective` |
| 1 | 1 | `Works but toxic` |
| 0 | 1 | `Toxic and doesn't work` |
| 0 | 0 | `Does nothing` |

**The biology in one line:** cancer cell membranes carry more negative charge
than healthy ones, so positively charged peptides (lots of K and R) get pulled
in and punch holes in them. The failure mode is peptides that punch holes in
red blood cells too. That is why there are two models.

### ⚠️ Two separate datasets

The anticancer and hemolytic datasets come from **different sources**. Train
each classifier **only on its own dataset**. Some peptides appear in both —
that's expected and fine. Do not merge them into one table.

### ⚠️ Demo data is fake

`participant_datasets/demo/` is randomly generated. It exists only to test that
your environment and file paths work. **Never train on it.**

## How we're judged (this drives every decision)

Ranking, in order:

1. **Average accuracy of the two classifiers** ← the primary metric
2. Total true positives
3. Average AUC
4. Average MCC

Tiebreak: probabilities, weighted toward correctly identified **Selective**
peptides.

**What this means for us:**

- Primary metric is plain **accuracy**, averaged over the two classifiers. Tune
  each threshold to maximize accuracy on a held-out split — but check
  sensitivity and specificity separately on each model. A model good at only one
  of those is not working.
- The organizers explicitly call out the shortcut: predicting `anticancer=1,
  hemolytic=0` for everything labels everything "Selective" with zero learning
  and scores badly. Don't drift toward it.
- **Two independent thresholds** to tune. They do not have to both be 0.5.
- Getting anticancer right but hemolytic wrong is only partial credit — the
  verdict is what's scored.

## Submission format (exact — the judging script is strict)

File generated by running our models on `final_test_sequences.csv`.

**Columns, in this order:**

```
sequence,anticancer_probability,anticancer_prediction,hemolytic_probability,hemolytic_prediction,verdict
```

- `sequence` — the peptide **exactly as given in the test file**
- `anticancer_probability` / `hemolytic_probability` — raw model output, 0 to 1
- `anticancer_prediction` / `hemolytic_prediction` — 1 or 0, from our thresholds
- `verdict` — one of: `Selective`, `Works but toxic`, `Toxic and doesn't work`,
  `Does nothing`

Note: the **test file** has `id` and `sequence`, but the **submission** keys on
`sequence`, not `id`. Don't carry `id` through.

Cross-check against `submission_template.csv` from the Drive folder before
submitting. If the format is off, the judging script ignores our entry.

## Decisions

Append decisions here so neither side redoes the argument.

- **Features (start here):** length, net charge (count K+R minus count D+E),
  amino acid composition (20 fractions), hydrophobicity (GRAVY), aromaticity,
  isoelectric point. All computable with Biopython + plain Python, all
  explainable to a judge. Dipeptide composition (400 pair counts) is the
  documented biggest single gain — add it second, with feature selection.
- **Hint from the organizers:** don't use every descriptor a library offers.
  Many are redundant. Keep the informative ones.
- **Model:** logistic regression as the baseline (fast, explainable), then
  random forest / SVM — a one-line change. Compare on the same split.
- **Validation:** hold out a split from the training data. Compare train vs
  validation accuracy; a big gap means memorizing.
- **Saving:** `joblib.dump` the whole pipeline (scaler + selector + model)
  together so `predict.py` can't drift from `train.py`.
- **(B, 13:05) Cross-validation is grouped by sequence similarity.** Both
  training sets contain clusters of near-identical peptides - the biggest is
  **42 sequences** in anticancer, 16 in hemolytic. Plain k-fold puts a peptide
  in one fold and its near-twin in another, so the model recognises rather than
  generalises and the reported accuracy comes out too high. `src/pep/leak.py`
  clusters by 3-mer Jaccard overlap and `StratifiedGroupKFold` keeps each
  cluster inside one fold. The scores below come from that, so they are honest
  but lower than a naive split prints. **If your split is not grouped, your
  numbers are not comparable to these.**
- **(B, 13:05) Both thresholds stay at 0.5.** Both training sets are exactly
  50/50, so 0.5 is the natural cut. Tuning on out-of-fold predictions moved
  anticancer to 0.555 for +0.2% accuracy while dropping sensitivity from 0.66
  to 0.59 - noise (fold-to-fold spread is +/-0.08) bought by half-ignoring a
  class, which costs true positives, the rank-2 criterion. `best_threshold`
  now only leaves 0.5 when tuning gains more than 1%.
- **(B, 13:05) No pretrained embeddings in the submission.** Tested ESM-2:
  anticancer accuracy **0.722 with it vs 0.739 with hand-made features**. It
  loses on merit, so the rules question around pretrained models is moot. The
  hand-made features are also the ones we can explain to a judge.
- **(B, 13:05) Dipeptide composition is the biggest single gain** on
  anticancer, exactly as the challenge doc predicts: phys 0.702 -> aac+phys
  0.721 -> aac+dpc+phys **0.739**. On hemolytic it added nothing (0.937 either
  way), so that model keeps the smaller, simpler feature set.

## How to produce a submission right now

```bash
# retrain (only if you change features or models) - about 35 s and 30 s
python src/train.py --train participant_datasets/initial/anticancer_train.csv --target anticancer --no-esm --out models/anticancer
python src/train.py --train participant_datasets/initial/hemolytic_train.csv  --target hemolytic  --no-esm --out models/hemolytic

# the 15:30 command - loads the saved models, trains nothing
python src/predict.py --input final_test_sequences.csv --output submissions/final.csv --template submission_template.csv
```

`predict.py` refuses to write a file that would be rejected. It checks column
order, rows in vs rows out, probabilities inside 0-1, predictions strictly 0/1,
verdict strings against the four allowed values, and the all-`Selective`
shortcut. Repeated sequences are a warning, never a block - a hard stop at
15:30 over something harmless is its own failure mode.
